## 🌸 About Sahara AI

**Sahara AI** is an AI-powered personal safety platform designed to provide **fast, intelligent, and reliable assistance during emergency situations**.

Instead of depending only on a traditional emergency call or manually opening a safety application, Sahara AI focuses on **early detection, instant emergency communication, live location awareness, voice-based activation, smartwatch integration, and intelligent response support.**

The core idea is simple:

> **A person should not have to unlock their phone, search for an app, explain the situation, and then ask for help when they are already in danger.**

Sahara AI is designed to reduce those steps and make emergency assistance **faster, simpler, and more accessible.**

---

# 🚨 The Problem

During an emergency, a person may:

* Be unable to unlock their phone
* Be unable to type a message
* Be unable to make a phone call
* Have their hands occupied
* Be scared or physically unable to react
* Lose network connectivity
* Have very little phone battery
* Be travelling alone
* Need help without attracting attention

Traditional safety applications often depend heavily on **manual interaction**.

Sahara AI addresses this gap by introducing a **multi-layer emergency response system**.

# 🆘 Special Features

## 1. 🎙️ Voice-Activated SOS

The user can trigger emergency assistance using a predefined voice command.

### Why it matters?

In dangerous situations, physically interacting with a phone may not be possible.

Instead of:

> Unlock → Open App → Press SOS

Sahara AI aims toward:

> **Voice Trigger → Emergency Mode**

This reduces interaction during critical moments.

---

# 2. 📍 Intelligent Location Sharing

When emergency mode is activated, Sahara AI can associate the emergency with the user's location.

The system can provide:

* Current location
* Location coordinates
* Emergency status
* Time of activation
* Location information for trusted contacts

This allows the responder to understand **where help may be required**.

---

# 3. ⌚ Smartwatch Integration

A major part of Sahara AI is the ability to use a **smartwatch as an additional safety interface**.

The smartwatch can act as:

* Emergency trigger
* Quick SOS interface
* Companion device
* Backup interaction point

### Important concept

> **The smartwatch is not replacing the smartphone.**

It works as an **additional emergency input device**.

This is useful because a smartwatch can be easier to access quickly than a phone.

---

# 4. 🔋 Low-Battery Safety System

One important situation often ignored by safety applications is:

> **What happens when the phone battery is about to die?**

Sahara AI introduces a low-battery awareness concept.

When battery becomes critically low, the system can prepare the emergency workflow by:

* Monitoring battery status
* Warning the user
* Preparing emergency information
* Supporting trusted-contact communication
* Sharing relevant last-known information where possible

The purpose is to reduce the risk of losing the safety connection unexpectedly.

---

# 5. 📱 Dead-Phone / Unreachable Device Awareness

Sahara AI considers another real-world scenario:

> **What if the person's phone becomes unreachable?**

Instead of assuming that:

> “No signal = person is safe”

the system treats device unavailability as an important safety condition.

The platform can be designed to maintain:

* Last known location
* Last known activity
* Emergency status
* Device connectivity state
* Battery information

This creates a more complete emergency context.

---

# 6. 🚨 Persistent Emergency Alert

An emergency alert should not simply disappear after being generated.

Sahara AI can maintain an active emergency state until the situation is appropriately handled.

Example:

```text
SOS ACTIVATED
      ↓
Emergency Mode
      ↓
Alert Generated
      ↓
Trusted Contact Notified
      ↓
Location Shared
      ↓
Emergency State Active
      ↓
User / Authorized Person Resolves Alert
```

This helps avoid accidental dismissal of an emergency state.

# 🔗 Frontend–Backend Integration

The frontend communicates with the backend through REST APIs.

```text
React Frontend
      ↓
HTTP Request
      ↓
FastAPI Backend
      ↓
Business Logic
      ↓
Database
      ↓
Response
      ↓
React UI
```

This separation allows the frontend and backend to be developed independently while remaining integrated through APIs.

### Backend API configuration

The frontend uses `VITE_API_URL` as its single backend base URL. In local Vite development it defaults to `http://127.0.0.1:8000`; set `VITE_API_URL` in the frontend deployment environment to the actual FastAPI URL before building for production. Do not put `DATABASE_URL`, `SECRET_KEY`, or Supabase service-role credentials in frontend variables.

Backend account sign-in and record synchronization are optional. Profile, trusted contacts (with a phone number), community reports, journeys, location updates, check-ins, and SOS records sync only after signing into the existing FastAPI account. Without a signed-in account, the existing browser-local experience remains available. Recording an SOS does not send SMS, place calls, or contact emergency services.
